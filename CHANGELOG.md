# Changelog

All notable changes to Claw Task Hub will be documented in this file.

## Unreleased

- Added control-plane surfaces to the UI. Issue detail has an Execution panel showing the latest attempt's state (provisioning, running, verifying, reviewable, accepted, failed, canceled, stale, or reconciling), workspace lease, verdict, conflicts, acceptance run, runnability, and attempt history. Its controls call the real handlers: launch, verify, accept, reject, cancel, quarantine, resume, reconcile, and retry. The project overview shows the runnable queue with reasons for waiting issues. `tests/control-plane-e2e.mjs` covers the whole path in a temporary repository through the API: claim, pinned base, leased worktree, a deterministic harness, diff and test evidence, reviewable, local acceptance, and claim release. It restarts the service mid-run and checks startup reconciliation quarantines and recovers the attempt, then exercises the served UI's controls and its error, responsive, and accessibility states in a browser. `CLAW_TASK_HUB_RECONCILE_MIN_AGE_MS` and `CLAW_TASK_HUB_RUNNER_STALE_MS` tune startup and periodic reconciliation.
- Added execution reconciliation: `reconcile_execution`, run at API server startup and every five minutes (`CLAW_TASK_HUB_RECONCILE=0` disables it; `CLAW_TASK_HUB_RECONCILE_INTERVAL_MS` sets the interval). It compares attempts, runner heartbeats, workspace leases, and Git worktrees, and records every decision in its run. It resumes interrupted acceptances, applies run outcomes whose finish transition was lost, and resumes failed, interrupted, or expired leases through provisioning. It quarantines lost runners, missing worktrees, moved branches, and drifted bases as `stale`, and releases leases held by terminal attempts. It never kills a process it cannot prove the hub started and never removes a dirty or unowned worktree; lapsed claims and unowned worktrees are reported. Work changed within `min_age_ms` is left alone, runs are bounded and hold a single lock, and repeated runs are safe. Runs now keep a supervisor heartbeat and record their outcome before the finish transition. `list_reconciliation_runs`, `get_reconciliation_run`, and `quarantine_execution_attempt` give operators inspection and quarantine, and test-only fault points (`CLAW_TASK_HUB_ENABLE_FAULT_INJECTION`) crash real processes at provisioning, run, and acceptance boundaries.
- Added policy-gated acceptance for execution attempts. Operators save revisioned acceptance policies per repository (`save_acceptance_policy`). `accept_execution_attempt` commits the leased worktree only when its tree is exactly the tree verification passed on. It can merge into a local branch with `git merge-tree` and a compare-and-set ref update, so no checkout is touched. It pushes only with `allow_push`, and opens and merges pull requests through a provider (`github` via the GitHub CLI, or a deterministic `fake`) only with `allow_pull_request` and `allow_provider_merge`. Runs are write-ahead records that resume by idempotency key, so a commit, push, or pull request is never repeated. Missing or stale verification, blocking conflicts, missing or checked-out merge targets, rejected pushes, and unavailable providers fail typed and leave the attempt reviewable; merge conflicts reject it with `merge_conflict`. Acceptance records the commit, merge, and pull request identities on the `accept` transition, then comments on the issue, releases the claim as completed, marks the issue Done, and releases the workspace while keeping the branch. `reject_execution_attempt` rejects with `review_rejected` and releases the claim idempotently. Credential values are scrubbed from all stored and returned output.
- Added touched-file conflict detection across concurrent execution attempts. Issues declare planned paths per repository (`declare_execution_paths`), and each attempt's latest diff evidence supplies observed paths. `detect_execution_conflicts` records overlaps between live attempts: exact paths including rename sources and deletions, declared directories, a labelled shared-directory heuristic, and, for different base commits, paths changed between the bases. Each record names both attempts, the path, both bases, the method, a certainty (observed, declared, heuristic, or unknown), the severity from the repository's operator conflict policy (`save_conflict_policy`; nothing blocks without one), and a resolution state. Overlaps that disappear resolve and returning ones reopen; `decide_execution_conflict` overrides or reopens with a required reason, and every change is kept in an append-only decision log. Blocking conflicts refuse `launch_execution_attempt` (`conflict_blocked`); blocking declared overlaps exclude issues from `list_runnable_issues` (`path_conflict`) and refuse unforced claims, while other overlaps are reported as `path_warnings`; capturing a diff and verifying re-detect conflicts, and verdicts record them for review.
- Added `list_runnable_issues` (store, CLI, MCP, and `GET /api/runnable-issues`) and a single owner of runnability in `server/issue-runnability.ts`. An issue is runnable when it is open and not archived, is not explicitly Blocked or Paused, belongs to no archived or closed project, has no open dependency, is not claimed by another active session, and has no live execution attempt. Every other open issue in scope is listed with all of its reason codes, including each blocker, claim, and attempt. Ordering is deterministic across SQLite and Postgres (priority, then issues that unblock the most, then age), and runnable and excluded issues page independently. `claim_issue` now asks the same owner whether an issue is blocked and runs in one transaction that locks the issue row on Postgres, so of two sessions racing for an unclaimed issue exactly one wins.
- Added structured execution evidence and policy-gated verification. Operators save revisioned verification policies per repository (`save_verification_policy`, `get_verification_policy`) whose steps are argument vectors run without a shell, never programs from the repository. `capture_execution_diff` records touched files, line counts, a patch hash, a bounded patch artifact, and the Git tree fingerprint of the worktree's exact content without touching its index. `record_execution_evidence` appends observations and claims tied to that fingerprint; records never change, and corrections supersede them. `verify_execution_attempt` runs the policy's steps with bounds, scrubbing, and cancellation, records a verdict, and moves the attempt to `reviewable` or to `failed` with `checks_failed`, `evidence_missing`, or `stale_base_evidence`; claims never satisfy a policy, and a passing verdict never accepts an attempt. Migration `0007_execution_attempts` now also creates `verification_policies` and `execution_evidence`.
- Added harness-neutral execution adapters and supervised runs: `launch_execution_attempt` starts a harness in an attempt's leased worktree through an adapter (`codex` for `codex exec --json` in the `workspace-write` sandbox, and a deterministic `fake` adapter enabled by `CLAW_TASK_HUB_ENABLE_FAKE_HARNESS=1`). Instructions are delivered on stdin only after the launch transition wins, so duplicate launches never start work. Harnesses get an allowlisted environment with declared credential variables passed through and scrubbed from captured output; output, wall-clock, and idle time are bounded; cancellation from any process terminates the harness process tree; and runs finish with `complete_run` or a typed `fail` carrying log artifacts and run details. Unknown adapters, unsupported capabilities, unavailable executables (including `.cmd` shims that would need a shell), and attempts without a ready workspace are refused before any process starts. `list_execution_adapters` reports what is available.
- Added leased Git workspaces for execution attempts: `provision_execution_workspace` (or `create_execution_attempt` with `repository_path`) creates a locked worktree on a branch derived from the attempt id, rooted at the pinned base commit, under `CLAW_TASK_HUB_WORKSPACE_ROOT` (default: `workspaces` next to the database). The operator's checkout is only read and its hooks do not run; the lease is recorded before Git runs, so interrupted or expired provisioning is verified and resumed by provisioning again. Foreign branches and directories, repository mismatches, roots inside the repository, missing bases, and base drift are refused without touching anything. `plan_`, `get_`, `list_`, `renew_`, and `release_execution_workspace` complete the lifecycle; release removes only a clean worktree and always keeps the branch.
- Added durable execution attempts through `create_execution_attempt`, `get_execution_attempt`, `list_execution_attempts`, and `transition_execution_attempt` in the store, CLI, MCP, and HTTP API. An attempt records its issue, claim, session, harness, repository, and an immutable base commit SHA; moves only through `planExecutionTransition` with a compare-and-set revision and an idempotency key, each recorded in a transition ledger; binds its workspace lease and process identity once; and is never rewritten by a retry, which creates a new attempt. A partial unique index allows one live attempt per issue across processes, deleting an issue with a live attempt requires `force=true`, and migration `0007_execution_attempts` upgrades existing SQLite databases.
- Specified the execution control plane contract: a versioned attempt lifecycle (provisioning, running, verifying, reviewable, accepted, failed, canceled, stale, reconciling) with actor authority, reason codes, typed transition failures, compare-and-set and idempotent replay, reconciliation origins, default bounds, and explicit local-only, dirty-checkout, path, command, credential, and operator-approval boundaries. `server/execution-contract.ts` is the single owner; `bun run contract:generate` renders its tables into `docs/AGENTIC_HARNESS.md` and `bun run contract:check` rejects drift.
- Made open UIs refresh when any hub sharing a Postgres database writes, including hubs in other processes and on other machines: activation installs statement-level `NOTIFY` triggers, and each API server relays the notifications to its UIs with a self-healing listener. It degrades to manual refresh on servers without triggers or `NOTIFY`.
- Added `bun run migrate:postgres`, a standalone operator tool that copies a SQLite hub into a registered Postgres/Supabase connection in one verified transaction, with a rollback-only `--dry-run`.
- Made registered Postgres/Supabase connections selectable as the active database from the database menu, `activate_database`, and the HTTP API, with schema applied on activation, a shared selection across UI/CLI/MCP processes, and a loud local fallback when a selected connection is unreachable at startup.
- Made the store layer run on Postgres: single-key upserts rendered from the SQLite multi-key definitions, Postgres full-text search, explicitly typed nullable parameters, and bigint/numeric results returned as numbers.

## [0.2.0]

- Made Bun 1.3.14 the single package-manager and runtime contract, including native `bun:sqlite` storage.
- Added complete project, issue, and managed-database CRUD across HTTP, CLI, and MCP with destructive confirmation guards.
- Added one canonical contribution gate, repository hooks, bounded pull-request CI, SemVer validation, packaged-runtime smoke tests, and tag-only GitHub Releases.
- Consolidated shared UI styling, repaired responsive detail layouts, removed misleading and duplicate controls, and added browser regressions for those states.
- Added explicit mutation notifications so open UIs refresh after successful API, CLI, or MCP writes without database polling.
- Made temporary SQLite test cleanup Windows-safe by isolating store-regression database handles in a worker process and retrying transient filesystem locks.
- Made database activation fully release the previous Bun SQLite connection so switched databases can be deleted on Windows.
- Applied SQLite's busy timeout before WAL negotiation so concurrent CLI startup waits instead of failing with `SQLITE_BUSY_RECOVERY`.
- Made release smoke teardown terminate and await the complete packaged process tree before retrying transient Windows filesystem locks.
- Added an append-only compatibility migration for existing issue dependency tables missing the current `source` field.
- Read SQLite's journal mode before rewriting it and retried contention-shaped `SQLITE_IOERR_*` failures, so concurrent hub startup on Windows no longer dies with `SQLITE_IOERR_TRUNCATE`.
